# RAY — Revenue Recovery Orchestrator

**RAY** is an AI-native revenue recovery decision system developed for the Razorpay AI Buildathon.

## Overview

RAY operates on payment failures, determining whether to create a Razorpay Payment Link or deliberately do nothing, based on expected incremental economic value.

## V1 Scope

RAY V1 focuses exclusively on:

- **Revenue Surface**: Payment failures only
- **Action Space**: `create_payment_link` or `do_nothing`
- **Decision Model**: LLM diagnosis → ML prediction → Economic optimization → Policy authorization → Execution

### What V1 Does NOT Include

- Subscriptions, invoices, checkout abandonment
- SMS, voice, or advanced retry orchestration
- Multiple recovery workflows
- Multi-agent architecture
- Contextual bandits, uplift modeling, or reinforcement learning

## Architecture

RAY follows a strict separation of concerns:

```
LLM (diagnosis/explanation)
  ↓
ML (recovery probability prediction)
  ↓
OPTIMIZER (economic action selection)
  ↓
POLICY ENGINE (authorization)
  ↓
EXECUTION (Razorpay Payment Link)
  ↓
OUTCOME ENGINE (actual result observation)
  ↓
EVALUATION (performance measurement)
```

## Technology Stack

- **Backend**: Python 3.14+ with FastAPI
- **Frontend**: Next.js with TypeScript
- **Database**: PostgreSQL
- **ML**: scikit-learn, LightGBM/XGBoost (evaluated)
- **LLM**: Provider abstraction

## Experimental Integrity

RAY's benchmark uses **synthetic data** with strict experimental controls:

- **Ground truth separation**: Hidden simulator variables never exposed to RAY
- **Data split**: 550 train / 150 validation / 300 test customers
- **Frozen baseline**: Historical recovery rate baseline
- **Reproducible seeds**: Explicit random seeds for all stochastic processes
- **Version tracking**: All components versioned

### Critical Rules

1. Test set is untouched until final evaluation
2. LLM diagnosis is cached offline, not live during benchmark
3. Simulator parameters frozen before evaluation begins
4. No simulator ground-truth variables used as decision inputs

## Setup

### Prerequisites

- Python 3.14+
- Node.js 22+
- PostgreSQL 14+

### Installation

```bash
# Backend setup
cd services/api
python -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Frontend setup
cd apps/web
npm install

# Database setup
createdb ray_dev
# Run migrations (TBD)
```

### Environment Variables

Copy `.env.example` to `.env` and configure:

```bash
# Database
DATABASE_URL=postgresql://user:pass@localhost:5432/ray_dev

# Razorpay (development)
RAZORPAY_KEY_ID=your_key_id
RAZORPAY_KEY_SECRET=your_key_secret

# LLM Provider
LLM_PROVIDER=anthropic  # or openai
LLM_API_KEY=your_api_key
```

## V1 Configuration Defaults

All values are **configuration assumptions** for the synthetic environment:

- `assumed_organic_recovery_rate`: 4%
- `max_actions_per_day`: 10
- `max_contacts_per_customer_per_day`: 1
- `do_not_contact_fraction`: 5%
- `autonomous_amount_limit`: ₹25,000
- `simulation_days`: 10
- `bootstrap_iterations`: 1,000
